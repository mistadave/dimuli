Rules for this plan:
- Owner rule (memory "device first"): picker, gallery and multi-image automation only on the emulator; no test images on the real phone. Emulator dimuli_api36 = `emulator-5554`; one emulator at a time. If `adb devices` does not list emulator-5554 as `device`, start it with `emulator -avd dimuli_api36 -port 5554 -no-snapshot-save -no-boot-anim` in the background (smoke.sh waits for boot).
- NEVER send scroll or mouse-wheel input to dimuli (Slint Android backend panics on it): no `input roll`, no `input scroll`. `input swipe` only while the Photo Picker has focus (check `adb -s emulator-5554 shell dumpsys window | grep mCurrentFocus`) and for drag gestures inside dimuli's canvas.
- dimuli buttons by screenshot coordinates (`adb -s emulator-5554 exec-out screencap -p > file.png`, then read the PNG); this AVD is 1080x2400 at 420 dpi, so physical px = logical px x 2.625. The picker's thumbnails and its confirm button by `uiautomator dump` bounds.
- Long-press swap with `adb -s emulator-5554 shell input motionevent DOWN x y`, wait 0.8 s (Slint long-press is 500 ms), `MOVE x2 y2`, `UP x2 y2`.
- Pinch zoom cannot be injected with `adb shell input` (single pointer); it is part of the owner check in 08-06, and zoom logic does not depend on the image count (host tests).
- Human-checks: the `<human-check>` items in Tasks 1 and 2 are NOT judged during this plan (the project's `workflow.human_verify_mode` is `end-of-phase`, so this plan stays autonomous). The executor only produces the named screenshots; their judgement is deferred to the owner checkpoint in 08-06 Task 2 step 9 (items a-h list every screenshot and expectation from both human-checks). The automated gates of this plan decide pass or fail here.
- Defects: record them with step and evidence. Fix only via `rust-coder` when the cause is clearly inside this phase's changes, then re-run the affected step and say so in the SUMMARY; otherwise stop and leave them for gap closure. Do NOT commit or push.
- Expected memory: 9 images peaked at VmHWM 500 624 kB on this AVD (06-06/06-08, 489 MiB); 08-03 keeps the preview budget constant, so 12 and 25 should stay near that (research A5). 1 GiB is half of the 2 GB AVD and the hard gate.

4. 12 images: `logcat -b all -c`; tap "Bilder wählen"; select the 12 newest photos in the picker (thumbnails by `uiautomator dump` bounds), tap the picker's confirm button and note the host time (`date +%s.%N`); poll `adb -s emulator-5554 logcat -d -s dimuli` every 0.5 s until `collage ready: 12 images` (timeout 180 s) and note the time; screenshot `p8-04-12-editor.png`. Tap "Speichern", note the time, poll for `saved to gallery: true`, note the time, screenshot `p8-04-12-saved.png`.
5. With dimuli still open: `adb -s emulator-5554 shell run-as ch.staeheli.dimuli cat /proc/$(adb -s emulator-5554 shell pidof ch.staeheli.dimuli)/status | grep -E 'VmHWM|VmRSS' > android/build/smoke/p8-04-mem-12.txt`; `logcat -d -s dimuli > android/build/smoke/p8-04-12-logcat.txt`; `logcat -d -b crash > android/build/smoke/p8-04-12-crash.txt`; write load and export seconds for 12 images into `android/build/smoke/p8-04-times.txt`.
